# oil-codex-title

让 Codex 侧边栏的话题名称保持容易辨认、容易找回。

未定名的话题在正常一轮结束后，由独立模型参考最近 3～5 轮有效对话与原始目标生成核心标题，程序拼接宿主提供的工作区后缀。首次成功定名并核验后永久冻结；后续内容、规则升级、工作区改名或迁移都不再触发模型或改名。只有用户明确要求的单次重命名可以改已定名标题。

## 安装与开始使用

这是本地 Codex 插件，适用于支持生命周期 Hook 的桌面版本。需要 Python 3.10+ 和已登录的兼容 Codex CLI；无需另外保存 API Key。默认使用 **GPT-5.6 Luna Fast，低推理档**（`service_tier=priority`），命名消耗当前账号的模型额度；Fast 会增加用量。

直接把下面这段话发给 Codex，让它查找仓库并完成安装：

```text
帮我查找 GitHub 仓库 amanayayatu-tech/oil-codex-title，安装 0.2.0-personal.1 完整插件（包含 UserPromptSubmit 与 Stop Hook，不要只安装 Skill），保留已有配置和标题记录。检查官方宿主 list_threads/list_projects 工具，启用 Hook 并运行 doctor；需要我在界面中信任 Hook 时，请告诉我具体操作。
```

安装完成后：

1. 让 Agent 执行插件中的 `doctor`，确认可执行文件和话题读取能力。
2. 确认 Codex 的 `features.hooks` 已开启；可通过 `codex features enable hooks` 开启。
3. 在 Codex 的 Hook 管理入口检查并信任本插件的 **UserPromptSubmit 与 Stop Hook**。CLI 使用 `/hooks`。安装插件本身不会自动信任 Hook；更新 Hook 定义后可能需要重新信任。
4. 在新的正常对话中验收，等待后台模型返回后检查侧边栏标题与本地日志。

需要信任的行为：UserPromptSubmit 在未定名时给主代理一条元数据准备指令；主代理在最终答复前，用官方 `list_threads(limit=50)` 和 `list_projects` 读取实际关联，通过 `workspace-context` 的 stdin 保存当前话题的最小工作区记录。Stop Hook 调用独立临时命名模型，并通过官方 `thread/name/set` 写入标题。两个 Hook 都不会恢复原话题、向其他话题发送消息或直接改写话题数据库。

必须能使用官方宿主项目工具。未关联时可只传 `threads`，但要由实际返回的 `projectId=null` 证明；已关联时必须能在 `projects` 返回值中找到同一项目。读取失败、来源不可用、记录超过 5 分钟或不属于当前轮次时保留原标题，后续正常轮次再处理。元数据在最终答复前准备，避免长任务提前取得的记录过期。

元数据通道信任当前主代理转交实际工具结果；本地程序校验结构与关联，不为 stdin 数据提供来源签名认证。完整工具列表用程序直接转交，不在当前对话中展开其他话题内容。

## 命名方式

标题固定为「emoji 对象｜目标（工作区）」：对象在前，目标在后，恰好一个全角分隔符。工作区使用侧栏的真实项目名称；明确未关联时写「本地项目」。前缀宽度最多 10 个英文字符，汉字按 2 计，恰好 5 个汉字完整显示，超出后加三个英文点 `...`。缩略只用于标题后缀。

首次命名或用户明确要求的重命名，参考近期用户实质需求的主要语言，保留产品名和技术名词；助手回答、代码及引用原文不决定标题语言。语言判断由同一次 Luna 命名完成，不额外调用语言检测模型。冻结后的标题不再自动切换语言。

已有成功命名记录的旧话题也按新规则冻结，不自动补后缀或更换图标。没有插件记录的历史话题仍可能在正常触发时完成一次命名；需要保留的标题可主动 `lock`。只有问候或信息不足时暂不冻结，等目标明确后再定名。

| 类型 | emoji |
| --- | --- |
| 内容制作 | 🎬 |
| 工具开发 | 🧩 |
| 对比调研 | 🔎 |
| 方法整理与文档 | 📝 |
| 日程安排 | 📅 |
| 页面设计 | 🎨 |
| 环境配置 | ⚙️ |
| 一般讨论 | 💬 |
| 命名与分类工具 | 🏷️ |
| 录音转写 | 🎙️ |
| 投资与金融研究 | 📈 |
| 网络、路由与代理 | 🌐 |
| 签到与积分 | 🎁 |

默认参考最近 5 轮有文字的对话。只有问候或确认且没有实质目标时不调用模型。模型只输出核心标题，工作区后缀由程序生成；完整后缀不占核心标题 48 字符的长度预算。命名规则集中在 `../prompts/naming.md`。

## 控制方式

Windows 命令使用 `py -3` 替代 `python3`。后台默认最多同时运行 2 个命名模型；`max_parallel_workers` 可设为 1～8，排队与格式复核共享单次模型超时预算。Stop 事件会短暂检查轮次完成状态，未完成或已过期的事件保留原标题并记录原因。

可以直接让 Agent「暂停自动命名」「固定这个话题的标题」「预览这个话题的新标题」「按新目标重命名这个话题」。暂停后恢复只对未定名话题生效；解锁不会清除已定名状态。

也可以在插件目录中运行：

```sh
python3 scripts/oil_codex_title.py doctor
python3 scripts/oil_codex_title.py status
python3 scripts/oil_codex_title.py usage
python3 scripts/oil_codex_title.py configure --model gpt-5.6-luna --service-tier fast
python3 scripts/oil_codex_title.py configure --model gpt-5.3-codex-spark --service-tier standard
python3 scripts/oil_codex_title.py rename <话题ID>
python3 scripts/oil_codex_title.py rename <话题ID> --apply
python3 scripts/oil_codex_title.py lock <话题ID>
python3 scripts/oil_codex_title.py unlock <话题ID>
python3 scripts/oil_codex_title.py pause
python3 scripts/oil_codex_title.py resume
```

`rename` 只用于用户明确请求，默认预览，`--apply` 才写入并读回核验。运行前先读取宿主项目工具，将实际 JSON 组成 `{"threads":话题工具结果,"projects":项目工具结果}`，通过 stdin 传给 `workspace-context <话题ID>`；此入口会用官方接口读取最新轮次，也可显式提供 `--turn <轮次ID>`。不能手工拼造关联或从目录名猜测。它不保证桌面置顶缓存已刷新；桌面限制见 [发布验收](发布验收.md)。

Fast 是服务档位，不是另一个模型 ID。Spark 使用标准档位，模型本身以速度为重点。切换模型时若未指定服务档位，程序会清除旧模型的 Fast 设置，避免把不支持的档位传给新模型。

## 数据与并发边界

`usage` 汇总新版启用后的独立模型账本，按命名/归档和模型分组，展示调用尝试、Token、未知用量与处理结果。缓存命中包含在输入 Token 内，推理 Token 包含在输出内；未知不等于零，不换算账号额度。账本先记录启动，再记录模型返回与最终处理状态，校验失败、过期结果、格式复核及重名重试均保留独立记录。超时或进程中断只有已返回的用量可统计，其他标为未知。

账本保存在数据目录的 `usage/日期/`，仅含时间、用途、模型、话题 ID、用量、耗时和状态，不含标题、原文或错误详情。它不统计宿主管理 Agent；旧日志不合并进账本，避免迁移时重复计数。保留日志中的纯确认跳过数另列，日志轮转后可能少于历史总数。

配置、每话题状态和简短日志默认位于 `$CODEX_HOME/oil-codex-title`；未设置 `CODEX_HOME` 时使用用户主目录下的 `.codex/oil-codex-title`。可用 `OIL_CODEX_TITLE_DATA` 指定独立测试目录。未知配置字段会保留。

对话摘录仅传给当前登录所使用的 Codex 模型服务；不向其他服务发送。插件不保存完整对话或命名提示词。临时模型会话使用 `--ephemeral`，输出临时文件用完删除。持久日志只记录状态、候选标题、简短理由与用量，每个话题按容量轮转。工作区记录保存在数据目录的 `workspaces/`，只存当前话题和轮次、项目 ID、项目名、核验时间和状态，不保存完整列表、其他话题摘要或绝对目录。

Stop Hook 只返回空 JSON；UserPromptSubmit 仅在未定名时追加元数据准备上下文，冻结后也返回空 JSON。主代理多出工具调用和相应上下文用量，不计入独立命名模型的 `usage` 账本。Codex 仍可能显示 Hook 的执行状态或宿主自身产生的错误。

同一话题使用进程锁；新 Hook 最多等待两个模型超时窗口加 20 秒，释放锁后重新判断最新轮次，避免漏掉快速连续对话的最后一次请求。重复内容跳过模型调用；独立模型禁用 Hook，避免递归。同工作目录中发现与已记录标题重名时最多额外生成一次，仍冲突就返回 ambiguous_title。写入前重新读取话题，如果标题或对话已变化，就丢弃旧结果。官方改名 API 没有原子条件更新，最后一次检查与写入之间仍存在极短的并发窗口。

插件首次成功写入并读回，或确认现有结构化标题准确后，永久停止自动处理。用户此后手工更名也保持原样。首次生成中若宿主改动了临时标题，本次结果会丢弃，等待后续正常轮次；首次处理前无法可靠区分宿主自动标题与用户手动标题，需要保留的标题请主动 `lock`。暂停或锁定不会取消已产生的模型费用。

## 兼容性与限制

- macOS：优先发现桌面 App 自带的 Codex；可用 `configure --codex-bin <路径>` 覆盖。
- Linux：保留 POSIX 内核锁，纳入跨平台自动化测试；桌面体验未实测。
- Windows：已适配原生启动、内核文件锁和 UTF-8；验收范围见 [Windows 安装与验证](Windows安装与验证.md)，不能把程序测试等同于桌面自动触发实测。
- 云端和 ChatGPT Work：不支持此本地话题适配器。
- 离线：可以查看配置和暂停，生成标题需要连接模型服务。
- 某些旧 CLI 无法读取桌面端的新存储格式；兼容性检查失败时保留原标题。
- 插件只响应安装之后实际触发的轮次，不自动扫描或批量修改历史话题。
- Hook 信任和功能开关由 Codex 管理；程序不会绕过或自行写入信任记录。
