## 个人版 0.2.0-personal.2（2026-11-07）

- **工作区修复**：官方话题列表可能给出 `projectId=null`，同时话题完整 `cwd` 与项目列表中唯一的本地项目 `path` 相同。旧版误写「本地项目」，在受影响话题上 F=10（每次出现），S=5（话题归属错误、降低找回能力）。新版先按项目 ID 关联；ID 为空时仅用两份官方结果中的完整路径精确匹配；路径不唯一、缺失或来源不可用时保留原标题。没有从目录名猜测。
- **回归**：本机 143 项测试通过，新增覆盖空项目 ID 的唯一路径匹配、无匹配、重复路径、显式纠正后缀仍保留核心标题，以及 Hook 事件名大小写和独立模型推理等级传参。`git diff --check` 通过。`doctor` 旧版对已信任 Hook 误报待信任：F=10（已信任时每次误报），S=3（误导验收）。新版用官方 `hooks/list` 的实际事件名验证为 ready。
- **真实宿主读回**：本机安装新版后保留原配置和记录；仅处理官方项目路径唯一、既有标题与冻结记录一致的旧误标标题，经官方标题接口逐条读回。少数直接替换后缀会重名的每日任务，按该轮实际处理日期区分。原始标题、项目名、话题 ID、路径和清单仅保留本地，不发布。
- **模型设置**：独立模型的 `reasoning_effort` 可配置并传到真实 CLI 参数；本机以 GPT-6 Luna/max 的实际模型调用验证过该参数，账本与输出仅在本地。旧版固定写死 low：F=10（每次调用），S=3（偏离用户指定等级）。默认仍是 low，不改变既有用户配置。
- **边界**：新版的自然 Hook 触发仍要在更新后的正常用户轮次中观察；本机旧版已有真实自然触发、命名和冻结证据，不能直接算作新版实测。桌面置顶缓存即时刷新、其他操作系统的真实桌面流程仍未闭合。完整标题纠正和模型调用的私有证据不随版本发布。

## 尚未闭合的桌面显示问题

在当前 macOS 桌面版本中，独立 App Server 的 thread/name/set 可以更新持久标题，但置顶列表可能继续使用旧缓存。通过主 Agent 调用宿主 set_thread_title 后，列表能显示新标题。

这两个结果不能混为一谈：后台元数据改名成功，不等于宿主所有位置立刻刷新。doctor 的 desktop_display 返回 not_verified；renamed 的 verification 为 metadata_only。

当前没有验证出可供第三方后台 Hook 稳定使用的桌面刷新通道。不会为了绕过这个限制去改写桌面私有状态文件、恢复原任务、自动插入用户消息或接入未经支持的私有协议。

因此，宣称“所有任务自动更新且桌面立即一致”的发布条件尚未满足。本次以预览版公开并保留这项限制；完整自动体验仍需要可验证的宿主刷新接口或修复。

## 可复现检查

1. 记录某个置顶任务的标题与轮次数量。
2. 在插件命令行执行 rename <任务ID> --apply。
3. 读回标题元数据，确认新名称已保存。
4. 使用宿主 list_threads 检查置顶任务名称。
5. 如果仍是旧名，使用宿主 set_thread_title 设置步骤 3 的同一个名称，再次检查。
6. 对照原任务记录，确认测试只写标题元数据。

这项检查必须与普通非置顶任务分别执行。不要把 ready、命令成功退出或模型输出候选标题当作桌面验收通过。
